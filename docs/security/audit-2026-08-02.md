# Security and privacy audit — 2026-08-02

> **Historical snapshot.** This document records the August 2, 2026 audit scope and findings as they existed at that point in development. It is intentionally not rewritten to describe the current application. For current security boundaries and CI controls, see **[SECURITY.md](../../SECURITY.md)**.

## Scope

This audit covers the pre-transcription Python application foundation:
configuration loading, logging, filesystem operations, workspace and artifact
paths, diagnostics, dependency resolution, GitHub Actions, runner-resource
inspection, and the dry-run FFprobe/fingerprinting boundary. There is no audio
decoder or speech model in scope because neither is implemented yet.

The review used manual source inspection, Ruff's security rules, the complete
branch-aware test suite, mutation testing for changed decision logic, and
`pip-audit` 2.10.1 against the locked runtime dependency export.

## Findings addressed

| Severity | Finding | Resolution |
|---|---|---|
| Medium | Routine filesystem logs contained complete local paths, which may encode participant IDs or study names. Failure tracebacks could disclose them again. | Paths and exception traces are absent by default; full paths require explicit opt-in. |
| Medium | Missing-input and artifact-collision messages exposed recording or artifact names on CLI stderr. | Typed exceptions retain paths for in-process handling, but public messages omit them; paths appear only in explicitly requested plan output or full-path logging. |
| Medium | Generic variables such as `OUTPUT_DIR` could collide with the host environment, and an ambient `.env` changed behavior based on launch directory. | Only `SCHOLION_*` variables are accepted; dotenv loading requires explicit `--config`. |
| Medium | Private job directories inherited the process umask and could be group/world-readable. | Private state, cache, models, and jobs are created or tightened to `0700` on POSIX; reserved files remain `0600`. |
| Low | Logging configuration cleared the process-wide root logger and read Structlog's private context attribute. | Scholion now owns only its named logger and tracks bound context through its public adapter. |
| Medium | Two GitHub Actions used moving major-version tags. | Checkout and Python setup actions are pinned to immutable commit SHAs. |
| Low | Host CPU and memory counts could overstate resources available inside containers. | Runner inspection now considers CPU affinity plus cgroup v2 CPU and memory limits. |
| Medium | A media probe could invoke network-capable FFmpeg protocols, expose native-tool errors, parse unbounded metadata, or silently plan against a changing input. | Dry-run probing resolves a local path, allows only `file`, uses no shell, suppresses stderr, selects metadata fields, bounds parser input, enforces a timeout, fingerprints the complete file, and compares file identity before and after inspection. |

The locked runtime dependency audit reported no known vulnerabilities on the
audit date. CI now repeats that audit using a pinned `pip-audit` release. Ruff's
security rules run as part of the normal lint gate.

- Path-disclosure policy: 100% (7/7).
- Runner inspection, typed values, and policy: 98.5% (193/196).
- Media value objects: 100% (115/115).
- FFprobe execution and parsing: 100% (200/200).

validated bounds, or arithmetic clamps whose inputs cannot cross zero.

## Existing controls confirmed

- Artifact files use exclusive creation and do not overwrite collisions.
- Reserved files use owner-only `0600` permissions.
- Atomic writes use a same-directory temporary file and `os.replace`.
- Artifact names reject traversal and cross-platform device names.
- Public output cannot overlap private state or cache roots.
- FFmpeg diagnostics and FFprobe inspection use argument vectors, executables
  resolved without a shell, timeouts, and captured output.
- CLI internal failures suppress private exception messages.
- JSON command output is isolated from logs on standard error.

## Residual risks

1. FFprobe is native parsing code. The JSON limit is applied after process
   completion, so a malicious file may still drive child-process CPU or output
   allocation until the timeout. FFmpeg decoding, model runtimes, downloaded
   weights, and hostile-media execution will add a much larger attack surface.
2. Scholion restricts FFprobe protocols but does not enforce process-wide
   network isolation. A future engine or plugin could introduce network access.
3. Files and transcripts are not encrypted or securely erased by Scholion.
   Filesystem snapshots, backups, swap, and SSD behavior remain outside its
   control.
4. Same-user processes can still race mutable parent directories or replace
   symlinked path components. Fully defending shared hostile directories would
   require descriptor-relative filesystem operations and a stricter trust
   model.
5. Model provenance, checksum verification, signed releases, and an SBOM
   publication process remain future supply-chain work.
6. Windows ACL semantics are not equivalent to POSIX mode bits. Windows and
   macOS CI exercise behavior, but OS-specific permission hardening needs
   native review before a stable release.

## Security claim supported at this stage

Scholion can accurately claim privacy-preserving local defaults, bounded local
media inspection, and a security-reviewed application foundation. It cannot
yet claim hardened media processing, regulatory compliance, encrypted research
storage, or a complete transcription security posture.
